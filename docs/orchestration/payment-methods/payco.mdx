## Introduction
PAYCO uses a **redirect-based payment flow**. When a customer selects PAYCO at checkout, they are redirected to PAYCO's interface via Stripe's local processor partner in South Korea to authenticate and confirm their payment, then returned to your website or app upon completion. PAYCO is a single-use payment method.

This guide explains the process of integrating PAYCO into your app or website using Payrails via Stripe.

## Pre-requisites

Before you start accepting PAYCO payments with Payrails, there are a few requirements you must meet:

1. Integrate with Payrails using one of our SDKs or our API
2. Configure a new integration account for PAYCO via **Stripe** as a Payment Service Provider.
3. Enable PAYCO as a payment method in your Stripe integration configuration. In the Payrails portal, navigate to **Settings → Integrations**, select your Stripe integration instance, and enable the **PAYCO** checkbox under Payment methods, then save the account.
4. Enable PAYCO as a payment option in your workflow.
5. Make sure you're sending the PAYCO-specific required meta fields in your requests (see Required meta fields below).

## Ways to integrate PAYCO

### Payrails SDK

The simplest way to use PAYCO with Payrails is to use our drop-in in your checkout flow. With this integration type, no additional work is required to accept payments with PAYCO except for handling success/failure screens for your users.

For a more flexible implementation using our SDK, you can use our `genericRedirectButton` element. See special instructions here for your client-side implementation.

### Server-to-server integration

You can integrate PAYCO by completely managing your own client-side implementation, and using Payrails APIs with a server-to-server integration to process PAYCO payments.

#### Parse PAYCO from lookup response

With a server-to-server integration, you can call our lookup payment options endpoint to get available payment options. As shown in the example below, you can see `payco` returned as an option of the `paymentCompositionOptions`.

```json
{
  "name": "lookup",
  "actionId": "0bb6413e-cabb-4074-99e6-9e815c69f25b",
  "executedAt": "2026-03-26T12:00:00.000000000Z",
  "data": {
    "paymentCompositionOptions": [
      {
        "integrationType": "redirect",
        "paymentMethodCode": "payco",
        "description": "PAYCO"
      }
    ]
  },
  "links": {
    "execution": "https://api.payrails.io/merchant/workflows/payment-acceptance/executions/83c534ac-13b7-43e6-b04b-f3e8b4eb4424",
    "authorize": {
      "method": "POST",
      "href": "https://api.payrails.io/merchant/workflows/payment-acceptance/executions/83c534ac-13b7-43e6-b04b-f3e8b4eb4424/authorize"
    }
  }
}
```

#### Pass PAYCO payment method in request to authorize payment with Payrails

You can then make a request to our authorize a payment endpoint with `payco` as the `paymentMethodCode`. See an example below:

```json
{
  "executionId": "c0fd1c51-e709-47e5-bfd1-5d1c98f7d990",
  "amount": {
    "value": "10000",
    "currency": "KRW"
  },
  "paymentComposition": [
    {
      "integrationType": "redirect",
      "paymentMethodCode": "payco",
      "amount": {
        "value": "10000",
        "currency": "KRW"
      }
    }
  ],
  "meta": {
    "order": {
      "billingAddress": {
        "name": "Minji",
        "lastName": "Kim",
        "country": {
          "code": "KR"
        }
      }
    }
  },
  "returnInfo": {
    "success": "https://mysuccessurl.com",
    "error": "https://myerrorurl.com"
  }
}
```

> **Note on amounts:** KRW is a zero-decimal currency. Amounts should be provided as whole numbers — e.g., `10000` for ₩10,000. The minimum amount is 100 KRW.

\>

> **Note:** PAYCO is a redirect-based, single-use payment method. After calling the authorize endpoint, the customer is redirected to Stripe's local processor partner to authenticate and authorize the payment. Once confirmed, the customer will be redirected back to the `returnInfo.success` URL.

#### Handle the redirect response

After the customer completes the payment, they will be redirected back to your `success` or `error` URL. You should then verify the payment status by checking the workflow execution status via the Payrails API or by listening to webhook notifications.

## Required meta fields

PAYCO requires the following fields to be present in every authorize request:

| Field                                     | Required | Notes                          |
| ----------------------------------------- | -------- | ------------------------------ |
| `meta.order.billingAddress.name`          | ✅ Yes    | Customer's first name          |
| `meta.order.billingAddress.lastName`      | ✅ Yes    | Customer's last name           |
| `meta.order.billingAddress.country.code`  | ✅ Yes    | ISO-2 country code (e.g. `KR`) |
| `returnInfo.success` / `returnInfo.error` | ✅ Yes    | Required for all redirect APMs |

### Customer regions

PAYCO is available to customers based in:

- South Korea 🇰🇷
