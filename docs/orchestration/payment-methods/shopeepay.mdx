## Introduction
ShopeePay uses a **redirect-based payment flow**. When a customer selects ShopeePay at checkout, they are redirected to ShopeePay's interface to authenticate and confirm their payment, then redirected back to your website or app upon completion. ShopeePay is a single-use payment method where customers must authenticate each payment.

This guide explains the process of integrating ShopeePay into your app or website using Payrails.

## Pre-requisites

Before you start accepting ShopeePay payments with Payrails, there are a few requirements you must meet:

1. Integrate with Payrails using one of our [SDKs](/docs/orchestration/checkout-sdks/index) or our [API](/docs/orchestration/checkout-sdks/accept-payments-via-api)
2. Configure a new [integration account](/docs/orchestration/integrations/index) for ShopeePay via **dLocal** as a Payment Service Provider. If you do not have a dLocal integration already configured in your workspace, please follow the [dLocal integration setup guide](/docs/orchestration/integrations/dlocal) first.
3. Enable ShopeePay as a payment method in your dLocal integration configuration. In the Payrails portal, navigate to **Settings → Integrations**, select your dLocal integration instance, and enable the **ShopeePay** checkbox under Payment methods, then save the account.
4. Enable ShopeePay as a [payment option](./set-up-payment-methods) in your workflow.
5. Make sure you're sending the ShopeePay-specific meta fields in your requests.

## Ways to integrate ShopeePay

### Payrails SDK

The simplest way to use ShopeePay with Payrails is to use our [drop-in](/docs/orchestration/checkout-sdks/web-v5-legacy/drop-in) in your checkout flow. With this integration type, no additional work is required to accept payments with ShopeePay except for handling success/failure screens for your users.

For a more flexible implementation using our SDK, you can use our `genericRedirectButton` element. See special instructions [here](/docs/orchestration/checkout-sdks/web-v5-legacy/elements#generic-redirect-element) for your client-side implementation.

### Server-to-server integration

You can integrate ShopeePay by completely managing your own client-side implementation, and using Payrails APIs with a server-to-server integration to process ShopeePay payments.

#### Parse ShopeePay from lookup response

With a server-to-server integration, you can call our [lookup payment options](/docs/orchestration/payment-acceptance/lookup-payment-options) endpoint to get available payment options. As shown in the example below, you can see `shopeePay` returned as an option of the `paymentCompositionOptions`.

```json
{
  "name": "lookup",
  "actionId": "0bb6413e-cabb-4074-99e6-9e815c69f25b",
  "executedAt": "2026-03-26T12:00:00.000000000Z",
  "data": {
    "paymentCompositionOptions": [
      {
        "integrationType": "redirect",
        "paymentMethodCode": "shopeePay",
        "description": "ShopeePay"
      }
    ]
  },
  "links": {
    "execution": "https://api.payrails.io/merchant/workflows/payment-acceptance/executions/83c534ac-13b7-43e6-b04b-f3e8b4eb4424",
    "authorize": {
      "method": "POST",
      "href": "https://api.payrails.io/merchant/workflows/payment-acceptance/executions/83c534ac-13b7-43e6-b04b-f3e8b4eb4424/authorize"
    }
  }
}
```

#### Pass ShopeePay payment method in request to authorize payment with Payrails

You can then make a request to our [authorize a payment endpoint](/reference/authorizeaction) with `shopeePay` as the `paymentMethodCode`. See an example below:

```json
{
  "executionId": "c0fd1c51-e709-47e5-bfd1-5d1c98f7d990",
  "amount": {
    "value": "3990000",
    "currency": "IDR"
  },
  "paymentComposition": [
    {
      "integrationType": "redirect",
      "paymentMethodCode": "shopeePay",
      "amount": {
        "value": "3990000",
        "currency": "IDR"
      }
    }
  ],
  "meta": {
    "customer": {
      "name": "Jane Doe",
      "email": "jane.doe@email.com",
      "country": {
        "code": "ID"
      }
    }
  },
  "returnInfo": {
    "success": "https://mysuccessurl.com",
    "error": "https://myerrorurl.com"
  }
}
```

> **Note on amounts:** IDR uses 2 decimal places. Amounts should be provided in the smallest currency unit — e.g., `3990000` for Rp39,900.00.
>
>
> **Note:** ShopeePay is a redirect-based, single-use payment method. After calling the authorize endpoint, the customer will be redirected to ShopeePay's interface to authenticate and confirm the payment. Once confirmed, the customer will be redirected back to the `returnInfo.success` URL. Make sure to provide valid `returnInfo` URLs in your authorization request.

#### Handle the redirect response

After the customer completes the payment on ShopeePay's side, they will be redirected back to your `success` or `error` URL. You should then verify the payment status by checking the workflow execution status via the Payrails API or by listening to webhook notifications.

## Supported currencies

ShopeePay via dLocal supports the following presentment currencies:

* IDR — Indonesian Rupiah
* PHP — Philippine Peso
* THB — Thai Baht

## Supported regions / countries

### Customer regions

ShopeePay is available to customers based in:

* Indonesia 🇮🇩
* Philippines 🇵🇭
* Thailand 🇹🇭

### Merchant regions

Merchants enabled for Indonesia, the Philippines, or Thailand can accept ShopeePay payments via dLocal.
