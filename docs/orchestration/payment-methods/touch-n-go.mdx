## Introduction
Touch 'n Go uses a **redirect-based payment flow**. When a customer selects Touch 'n Go at checkout, they are redirected to the Touch 'n Go app or web interface to authenticate and confirm their payment, then redirected back to your website or app upon completion. Touch 'n Go is a single-use payment method where customers must authenticate each payment.

This guide explains the process of integrating Touch 'n Go into your app or website using Payrails.

## Pre-requisites

Before you start accepting Touch 'n Go payments with Payrails, there are a few requirements you must meet:

1. Integrate with Payrails using one of our [SDKs](/docs/orchestration/checkout-sdks/index) or our [API](/docs/orchestration/checkout-sdks/accept-payments-via-api)
2. Configure a new [integration account](/docs/orchestration/integrations/index) for Touch 'n Go via **dLocal** as a Payment Service Provider. If you do not have a dLocal integration already configured in your workspace, please follow the [dLocal integration setup guide](/docs/orchestration/integrations/dlocal) first.
3. Enable Touch 'n Go as a payment method in your dLocal integration configuration. In the Payrails portal, navigate to **Settings → Integrations**, select your dLocal integration instance, and enable the **Touch 'n Go** checkbox under Payment methods, then save the account.
4. Enable Touch 'n Go as a [payment option](set-up-payment-methods) in your workflow.
5. Make sure you're sending the Touch 'n Go-specific meta fields in your requests.

## Ways to integrate Touch 'n Go

### Payrails SDK

The simplest way to use Touch 'n Go with Payrails is to use our [drop-in](/docs/orchestration/checkout-sdks/web/drop-in) in your checkout flow. With this integration type, no additional work is required to accept payments with Touch 'n Go except for handling success/failure screens for your users.

For a more flexible implementation using our SDK, you can use our `genericRedirectButton` element. See special instructions [here](/docs/orchestration/checkout-sdks/web/elements#generic-redirect-element) for your client-side implementation.

### Server-to-server integration

You can integrate Touch 'n Go by completely managing your own client-side implementation, and using Payrails APIs with a server-to-server integration to process Touch 'n Go payments.

#### Parse Touch 'n Go from lookup response

With a server-to-server integration, you can call our [lookup payment options](/docs/orchestration/payment-acceptance/lookup-payment-options) endpoint to get available payment options. As shown in the example below, you can see `touchNGo` returned as an option of the `paymentCompositionOptions`.

```json
{
  "name": "lookup",
  "actionId": "0bb6413e-cabb-4074-99e6-9e815c69f25b",
  "executedAt": "2026-03-26T12:00:00.000000000Z",
  "data": {
    "paymentCompositionOptions": [
      {
        "integrationType": "redirect",
        "paymentMethodCode": "touchNGo",
        "description": "Touch 'n Go"
      }
    ]
  },
  "links": {
    "execution": "https://api.payrails.io/merchant/workflows/payment-acceptance/executions/83c534ac-13b7-43e6-b04b-f3e8b4eb4424",
    "authorize": {
      "method": "POST",
      "href": "https://api.payrails.io/merchant/workflows/payment-acceptance/executions/83c534ac-13b7-43e6-b04b-f3e8b4eb4424/authorize"
    }
  }
}
```

#### Pass Touch 'n Go payment method in request to authorize payment with Payrails

You can then make a request to our [authorize a payment endpoint](/reference/authorizeaction) with `touchNGo` as the `paymentMethodCode`. See an example below:

```json
{
  "executionId": "c0fd1c51-e709-47e5-bfd1-5d1c98f7d990",
  "amount": {
    "value": "5000",
    "currency": "MYR"
  },
  "paymentComposition": [
    {
      "integrationType": "redirect",
      "paymentMethodCode": "touchNGo",
      "amount": {
        "value": "5000",
        "currency": "MYR"
      }
    }
  ],
  "meta": {
    "customer": {
      "name": "Ahmad bin Ali",
      "email": "ahmad.ali@email.com",
      "country": {
        "code": "MY"
      }
    }
  },
  "returnInfo": {
    "success": "https://mysuccessurl.com",
    "error": "https://myerrorurl.com"
  }
}
```

> **Note on amounts:** MYR uses 2 decimal places. Amounts should be provided in the smallest currency unit — e.g., `5000` for RM50.00.
>
>
> **Note:** Touch 'n Go is a redirect-based, single-use payment method. After calling the authorize endpoint, the customer will be redirected to the Touch 'n Go app or web interface to authenticate and confirm the payment. Once confirmed, the customer will be redirected back to the `returnInfo.success` URL. Make sure to provide valid `returnInfo` URLs in your authorization request.

#### Handle the redirect response

After the customer completes the payment, they will be redirected back to your `success` or `error` URL. You should then verify the payment status by checking the workflow execution status via the Payrails API or by listening to webhook notifications.

## Supported currencies

Touch 'n Go via dLocal supports the following presentment currency:

* MYR — Malaysian Ringgit

## Supported regions / countries

### Customer regions

Touch 'n Go is available to customers based in:

* Malaysia 🇲🇾

### Merchant regions

Merchants enabled for Malaysia can accept Touch 'n Go payments via dLocal.
