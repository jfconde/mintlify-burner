## Introduction
QRIS uses a **redirect-based payment flow**. When a customer selects QRIS at checkout, they are redirected to a hosted page displaying a QR code. The customer scans the QR code using their preferred banking or e-wallet app to confirm payment, then returns to your website or app upon completion. QRIS is a single-use payment method.

This guide explains the process of integrating QRIS into your app or website using Payrails.

## Pre-requisites

Before you start accepting QRIS payments with Payrails, there are a few requirements you must meet:

1. Integrate with Payrails using one of our [SDKs](/docs/orchestration/checkout-sdks/index) or our [API](/docs/orchestration/checkout-sdks/accept-payments-via-api)
2. Configure a new [integration account](/docs/orchestration/integrations/index) for QRIS via **dLocal** as a Payment Service Provider. If you do not have a dLocal integration already configured in your workspace, please follow the [dLocal integration setup guide](/docs/orchestration/integrations/dlocal) first.
3. Enable QRIS as a payment method in your dLocal integration configuration. In the Payrails portal, navigate to **Settings → Integrations**, select your dLocal integration instance, and enable the **QRIS** checkbox under Payment methods, then save the account.
4. Enable QRIS as a [payment option](./set-up-payment-methods) in your workflow.
5. Make sure you're sending the QRIS-specific meta fields in your requests.

## Ways to integrate QRIS

### Payrails SDK

The simplest way to use QRIS with Payrails is to use our [drop-in](/docs/orchestration/checkout-sdks/web-v5-legacy/drop-in) in your checkout flow. With this integration type, no additional work is required to accept payments with QRIS except for handling success/failure screens for your users.

For a more flexible implementation using our SDK, you can use our `genericRedirectButton` element. See special instructions [here](/docs/orchestration/checkout-sdks/web-v5-legacy/elements#generic-redirect-element) for your client-side implementation.

### Server-to-server integration

You can integrate QRIS by completely managing your own client-side implementation, and using Payrails APIs with a server-to-server integration to process QRIS payments.

#### Parse QRIS from lookup response

With a server-to-server integration, you can call our [lookup payment options](/docs/orchestration/payment-acceptance/lookup-payment-options) endpoint to get available payment options. As shown in the example below, you can see `qris` returned as an option of the `paymentCompositionOptions`.

```json
{
  "name": "lookup",
  "actionId": "0bb6413e-cabb-4074-99e6-9e815c69f25b",
  "executedAt": "2026-03-26T12:00:00.000000000Z",
  "data": {
    "paymentCompositionOptions": [
      {
        "integrationType": "redirect",
        "paymentMethodCode": "qris",
        "description": "QRIS"
      }
    ]
  },
  "links": {
    "execution": "https://api.payrails.io/merchant/workflows/payment-acceptance/executions/83c534ac-13b7-43e6-b04b-f3e8b4eb4424",
    "authorize": {
      "method": "POST",
      "href": "https://api.payrails.io/merchant/workflows/payment-acceptance/executions/83c534ac-13b7-43e6-b04b-f3e8b4eb4424/authorize"
    }
  }
}
```

#### Pass QRIS payment method in request to authorize payment with Payrails

You can then make a request to our [authorize a payment endpoint](/reference/authorizeaction) with `qris` as the `paymentMethodCode`. See an example below:

```json
{
  "executionId": "c0fd1c51-e709-47e5-bfd1-5d1c98f7d990",
  "amount": {
    "value": "1500000",
    "currency": "IDR"
  },
  "paymentComposition": [
    {
      "integrationType": "redirect",
      "paymentMethodCode": "qris",
      "amount": {
        "value": "1500000",
        "currency": "IDR"
      }
    }
  ],
  "meta": {
    "customer": {
      "name": "Jane Doe",
      "email": "jane.doe@email.com",
      "country": {
        "code": "ID"
      }
    }
  },
  "returnInfo": {
    "success": "https://mysuccessurl.com",
    "error": "https://myerrorurl.com"
  }
}
```

> **Note on amounts:** IDR uses 2 decimal places. Amounts should be provided in the smallest currency unit — e.g., `1500000` for Rp15,000.00.
>
>
> **Note:** QRIS is a redirect-based, single-use payment method. After calling the authorize endpoint, the customer will be redirected to a hosted page displaying a QR code. The customer scans this with any participating banking or e-wallet app. Once confirmed, the customer will be redirected back to the `returnInfo.success` URL. QRIS payments expire in **2 days** if unpaid.

#### Handle the redirect response

After the customer completes the payment, they will be redirected back to your `success` or `error` URL. You should then verify the payment status by checking the workflow execution status via the Payrails API or by listening to webhook notifications.

## Supported currencies

QRIS via dLocal supports the following presentment currency:

* IDR — Indonesian Rupiah

## Supported regions / countries

### Customer regions

QRIS is available to customers based in:

* Indonesia 🇮🇩

### Merchant regions

Merchants enabled for Indonesia can accept QRIS payments via dLocal.
